Data quality checklist

  • Completeness: mandatory fields are populated.
  • Uniqueness: business keys do not contain unintended duplicates.
  • Validity: values conform to accepted formats and ranges.
  • Referential integrity: child keys map to valid parent records.
  • Freshness: latest source update is within the expected SLA.
  • Reconciliation: source and target counts/totals balance within defined rules.

Common design decisions

  • Partition by useful query predicates and avoid excessive small files.
  • Retain source metadata and processing timestamps for traceability.
  • Use schema evolution deliberately with compatibility checks.
  • Separate orchestration, transformation logic and monitoring.
