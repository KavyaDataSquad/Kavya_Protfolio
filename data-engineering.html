PySpark ingestion example

from pyspark.sql.functions import current_timestamp, input_file_name

source_df = (spark.read
    .option("header", True)
    .option("inferSchema", True)
    .csv("/mnt/source/customer/*.csv"))

bronze_df = (source_df
    .withColumn("ingested_at", current_timestamp())
    .withColumn("source_file", input_file_name()))

(bronze_df.write
    .format("delta")
    .mode("append")
    .saveAsTable("bronze.customer_raw"))

Incremental processing

Maintain a reliable watermark such as source_updated_at or an ingestion sequence. Read only records newer than the last successful watermark, write them to a staging Delta table, validate counts and keys, then merge into the curated target. Advance the watermark only after the target merge and audit logging succeed.

Delta Lake MERGE pattern

MERGE INTO silver.customer AS target
USING staging.customer_delta AS source
ON target.customer_id = source.customer_id
WHEN MATCHED AND source.updated_at > target.updated_at
  THEN UPDATE SET *
WHEN NOT MATCHED
  THEN INSERT *;

SCD Type 2 dimension

Keep history by expiring the current row and inserting a new version when tracked attributes change. Typical columns: business_key, attributes, effective_start_date, effective_end_date, is_current and record_hash.

-- Conceptual SCD2 merge sequence
-- 1. Detect changed business keys using a hash of tracked attributes.
-- 2. Expire the current version: is_current = false,
--    effective_end_date = change_timestamp.
-- 3. Insert the new version with is_current = true,
--    effective_start_date = change_timestamp,
--    effective_end_date = '9999-12-31'.

Operational controls

  • Schema validation and quarantine for malformed records.
  • Idempotent reruns and duplicate protection.
  • Source-to-target count reconciliation and rejected-row metrics.
  • Run audit table with start/end time, status, watermark and processed counts.
  • Retry transient failures; alert on repeated or data-quality failures.
