Join and aggregate

SELECT c.customer_segment,
       COUNT(DISTINCT o.order_id) AS order_count,
       SUM(o.sales_amount) AS revenue
FROM dbo.Orders AS o
JOIN dbo.Customers AS c
  ON c.customer_id = o.customer_id
GROUP BY c.customer_segment;

CTE and running total

WITH monthly_sales AS (
  SELECT DATEFROMPARTS(YEAR(order_date), MONTH(order_date), 1) AS month_start,
         SUM(sales_amount) AS revenue
  FROM dbo.Orders
  GROUP BY DATEFROMPARTS(YEAR(order_date), MONTH(order_date), 1)
)
SELECT month_start, revenue,
       SUM(revenue) OVER (ORDER BY month_start
         ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS running_revenue
FROM monthly_sales;

Deduplicate with ROW_NUMBER

WITH ranked AS (
  SELECT *, ROW_NUMBER() OVER (
    PARTITION BY customer_id
    ORDER BY updated_at DESC, source_id DESC
  ) AS rn
  FROM staging.Customer
)
SELECT * FROM ranked WHERE rn = 1;

Find unmatched keys

SELECT s.customer_id
FROM staging.Orders AS s
LEFT JOIN dbo.Customers AS d
  ON d.customer_id = s.customer_id
WHERE d.customer_id IS NULL;

Performance checklist

  • Return only required columns; avoid SELECT * in production queries.
  • Filter early and check whether predicates are sargable.
  • Review execution plans, logical reads and join strategies.
  • Index selective join/filter columns based on workload evidence.
  • Keep statistics current and avoid unnecessary functions on filtered columns.
  • Validate row counts and totals after query rewrites.
Examples use SQL Server-style syntax. Adjust date functions, identity handling and merge syntax for Oracle, PostgreSQL or other engines.
